1화

대표님 지시: "데이터로 뭘 좀 해 봐"

8쪽
한 줄 핵심분석은 무엇을(대상, What)과 어떻게(방법, How)를 아느냐 모르느냐로 4가지. 대표님의 막연한 지시는 둘 다 모르는 발견 칸에서 시작해요.
최적화대상도 방법도 앎. 이미 아는 문제를 더 잘 푸는 것
솔루션대상은 앎, 방법을 모름. 해결 방법을 찾아내는 것
통찰방법은 앎, 대상을 모름. 하던 분석으로 들여다보다 새로 깨닫는 것
발견둘 다 모름. 대상부터 새로 찾아내는 것
위 줄(대상을 앎)은 해결 계열(최적화, 솔루션), 아래 줄(대상을 모름)은 깨달음 계열(통찰, 발견). "방법을 모르면 솔루션(해결책)을 찾는다"로 하나만 잡으면 나머지가 자리 잡혀요.
통찰과 솔루션이 자주 뒤바뀌어 나와요. 통찰은 "방법(How)은 아는데 대상(What)을 모름", 솔루션은 그 반대예요.

대표님은 "다음 달 회의 때 뭐라도 보여 줘"와 "우리도 데이터 회사가 돼야지"를 동시에 말해요. 그래서 김 팀장은 빠른 성과(Quick Win)로 신뢰를 얻으면서 장기 계획을 함께 세우기로 해요.

시작 전에 따져 볼 3가지 (분석 기획 시 고려사항)

① 가용 데이터

지금 쓸 수 있는 데이터가 뭔가? 근태, 급여, POS는 있고, 퇴사 면담 기록은 종이뿐.

② 유스케이스

비슷한 성공 사례(유사 시나리오)가 있나? 다른 프랜차이즈의 퇴사 예측 사례 찾기.

③ 장애요소 대비

막힐 곳을 미리 계획. 개인정보 동의, 점주 반발, 담당자 교육.

"Accuracy & Deploy"를 과제 중심 쪽 보기로 섞어 내요. Speed, Quick, Solving = 과제 중심 / Accuracy, Long, Definition = 마스터플랜.

3화

사람마다 제멋대로면 곤란하다: 방법론

8쪽
한 줄 핵심순서가 없으면 경험 많은 사람만 분석할 수 있고, 매번 결과물 모양이 달라요. 그래서 절차, 방법, 도구, 양식을 묶은 표준 순서(방법론)를 쓴다. 그 뼈대가 단계 → 태스크 → 스텝.

큰 상자부터: 단계 ⊃ 태스크 ⊃ 스텝. 스텝은 며칠 안에 끝나는 작업 묶음(Work Package).

필기 용어 연결

방법론 구성요소절차, 방법, 도구와 기법, 템플릿과 산출물. 요리책으로 치면 순서, 조리법, 조리도구, 완성 사진.
계층적 프로세스 모델방법론을 단계 → 태스크 → 스텝 3층으로 쪼갠 뼈대. 7화의 빅데이터 분석 방법론이 이 모양.
기준선 (Baseline)단계가 끝날 때 확정해 두는 결과물. 이후 변경은 정식 절차로만.
Work Package스텝 = 짧은 기간에 끝내는 작업 묶음 (WBS의 맨 아래 칸)
구성요소 "아닌 것"으로 예산, 인력 같은 그럴듯한 보기가 나와요. 방법론은 일하는 순서와 양식이지 자원이 아니에요.

한 번에 쭉? 조금씩 돌며?: 개발 모델 4가지

8~9쪽
한 줄 핵심요구사항이 확실하면 계단처럼 한 번에(폭포수), 뭘 원하는지 모르면 시안부터(프로토타입), 위험이 크면 돌며 위험 제거(나선형), 현장 의견이 자주 바뀌면 짧게 자주(애자일).
폭포수 (Waterfall)

앞 단계가 끝나야 다음 단계

위에서 아래로(Top-Down) 한 방향. 요구사항이 확실한 급여 시스템 교체에 맞음. 중간에 바꾸기 어려움.

프로토타입 (Prototype)

일부를 먼저 만들고 보완

대표님도 뭘 원하는지 모를 때 대시보드 시안부터 보여 주고 고침. 7장 상향식과 연결.

나선형 (Spiral)

반복하며 점진 완성, 위험 제거

돌 때마다 위험을 점검. 전국 300곳 시스템처럼 크고 위험한 사업.

애자일 (Agile)

짧은 주기, 고객 피드백 반복

2주마다 점장들 의견을 받아 바로 반영. 민첩하게.

"반복"은 나선형과 애자일 둘 다 해요. 위험요소 제거가 보이면 나선형, 짧은 주기·고객 피드백이 보이면 애자일.
5화

데이터 더미에서 지식을 캐는 순서: KDD

9쪽
한 줄 핵심KDD는 이름 그대로 데이터베이스에서 지식 발견(Knowledge Discovery in Databases). 데이터를 고르고, 청소하고, 줄이고, 캐고, 평가하는 5단계.
KDD 5단계선전변마평
① 데이터
선택→② 전처리→③ 변환→④ 데이터
마이닝→⑤ 결과
평가
단계김 팀장 프로젝트에서한 단어로
① 데이터 선택근태, 급여, 매장 데이터 중 바리스타 1년치를 골라 목표 데이터 만들기고르기
② 전처리빈칸(결측), 튀는 값(이상값), 잡음 정리청소
③ 변환변수 50개 중 쓸 것만 고르기(변수 선택), 비슷한 것끼리 합치기(차원 축소)다이어트
④ 데이터 마이닝분류, 군집 같은 기법으로 퇴사 패턴 찾기캐기
⑤ 결과 평가찾은 패턴이 쓸 만한 지식인지 해석하고 평가감정
"변수 선택, 차원 축소"는 변환, "잡음, 이상값, 결측 처리"는 전처리. 둘 다 데이터를 손보는 단계라 서로 바꿔서 출제돼요. 청소(전처리) 다음에 다이어트(변환).
6화

업무에서 출발해 현장에 까는 순서: CRISP-DM

9쪽
한 줄 핵심KDD는 데이터 고르기부터 시작하지만, 김 팀장은 "퇴사가 왜 문제인지"부터 정리하고 싶어요. CRISP-DM은 업무 이해로 시작해 전개(현장 적용)로 끝나는 6단계이고, 단계 사이를 오가며 반복할 수 있어요.
단계하는 일 (교재 키워드)김 팀장 버전
업무 이해목적 파악, 상황 파악, 목표 설정, 계획 수립"6개월 내 퇴사를 30% 줄이자"
데이터 이해초기 수집, 기술 분석, EDA, 품질 확인근태 파일을 열어 보니 빈칸이 많네
데이터 준비데이터셋 선택, 정제, 통합 (분석용 데이터 만들기)근태 + 급여 + 매장 매출을 한 표로
모델링기법 선택, 테스트 계획, 모델 작성과 평가퇴사 예측 모델 만들기
평가분석 결과 평가, 모델링 과정 평가, 적용성 평가"이걸로 진짜 퇴사가 줄겠나?"
전개전개 계획, 모니터링·유지보수 계획, 종료 보고서, 리뷰전국 점장 화면에 위험 알림 띄우기
CRISP-DMCross Industry Standard Process for Data Mining. 업종 가리지 않는 데이터 마이닝 표준 순서
전개 (Deployment)만든 모델을 실제 업무에 까는 것
업데데모평전 ("업데이트 모델 평가전"). 데이터 두 번(이해, 준비)은 "열어 보고 → 다듬고" 순서.
EDA와 품질 확인은 데이터 이해 단계예요. "데이터를 손보는" 데이터 준비와 헷갈리지 않게: 이해 = 들여다보기, 준비 = 손보기.

끝

확인 8문제

답을 떠올려 본 뒤 눌러서 확인하세요.

대상은 아는데 방법을 모르면? 방법은 아는데 대상을 모르면?

앞은 솔루션(방법을 찾아야 함), 뒤는 통찰(하던 분석으로 들여다보다 깨달음). 둘 다 모르면 발견, 둘 다 알면 최적화.

Quick & Win은 과제 중심? 마스터플랜?

과제 중심(Speed & Test, Problem Solving). 마스터플랜은 Accuracy & Deploy, Long Term View, Problem Definition.

방법론 구성요소 4가지는?

절차, 방법, 도구와 기법, 템플릿과 산출물. 예산, 인력은 아님.

계층적 프로세스 모델을 큰 것부터?

단계 → 태스크 → 스텝. 단계는 기준선(Baseline)으로 관리, 스텝은 Work Package.

반복하며 위험요소 제거에 초점을 둔 모델은?

나선형. 짧은 주기와 고객 피드백이면 애자일.

KDD에서 차원 축소는 어느 단계?

변환(다이어트). 결측·이상값 처리는 전처리(청소). 순서 "선전변마평".

CRISP-DM에서 EDA와 품질 확인은 어느 단계?

데이터 이해. 순서 "업데데모평전", 업무 이해로 시작해 전개로 끝.

빅데이터 분석 방법론에서 위험 계획은 어느 단계? 대응 4가지는?

분석 기획 단계(SOW 작성과 함께). 대응은 회피, 전이, 완화, 수용. "확대"는 없음.

6장 한 문장

"데이터로 뭘 해 봐"라는 막연한 지시(발견)를 받은 김 팀장이 빠른 성과와 장기 계획을 함께 잡고, 사람마다 제각각이 되지 않게 표준 순서(방법론)를 빌려 온다: 데이터에서 캐는 KDD(선전변마평), 업무에서 시작하는 CRISP-DM(업데데모평전), 교재 표준 빅데이터 분석 방법론(기준분구평, 위험은 기획 단계에서).
