김 팀장, 분석할 거리를 찾아 나서다

6장에서 커피 프랜차이즈 본사 김 팀장은 표준 순서(방법론)를 손에 넣었어요. 7장은 그 순서의 맨 앞, "그래서 뭘 분석하지?"를 찾는 법(과제 발굴)과, 찾은 과제를 프로젝트로 굴리는 법(관리 10영역)이에요.

시간 없을 때 10분검은 상자 + 그림만
보통 25분필기 연결 칸까지
여유 있을 때회색 칸(+)도 펼치기
이 단원 전체를 한 문장으로문제를 알면 위에서 아래로 원인을 파고(하향식), 문제를 모르면 데이터를 먼저 보며 아래에서 위로(상향식) 찾고, 둘을 섞어 넓혔다 좁힌 뒤(혼합), 찾은 과제를 문서로 정리해 10개 영역으로 관리한다.

1화

같은 회사, 두 가지 출발점

10쪽
한 줄 핵심대표님이 "바리스타가 너무 그만둔다"고 문제를 콕 집어 주면 하향식, "뭔가 이상한데 뭔지 모르겠다"면 데이터부터 펼쳐 보는 상향식. 6장 4유형으로 치면 하향식은 문제(대상)를 아는 쪽, 상향식은 모르는 쪽이에요.
하향식 (Top-Down)

문제가 주어짐 → 해답을 찾음

문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토

"왜(Why) 그만두나?"를 파고듦

상향식 (Bottom-Up)

문제 정의 자체가 어려움 → 데이터로 인식

프로세스 분류 → 프로세스 흐름 분석 → 분석요건 식별 → 분석요건 정의

"무엇(What)이 보이나?"를 관찰

"프로세스 분류 → 흐름 분석 → 요건 식별 → 요건 정의"를 하향식 절차 보기에 섞어 내요. "프로세스", "요건"이 보이면 상향식, "문제", "타당성"이 보이면 하향식.

3화

하향식 ②③④ 정의하고, 방법 찾고, 따져 보기

10쪽
한 줄 핵심"퇴사가 많다"는 그대로는 분석할 수 없어요. 데이터로 답할 수 있는 질문으로 바꾸고(문제 정의), 누가 어떤 도구로 풀지 고르고(해결방안), 돈, 데이터, 기술로 해낼 수 있는지 따져요(타당성).
하향식 4단계
문제 탐색→문제 정의→해결방안 탐색→타당성 검토
비즈니스 문제

"바리스타가 너무 그만둔다"

사람 말로 된 걱정. 그대로는 계산할 수 없음.

데이터 문제

"입사 90일 안에 퇴사할 직원을 근태·급여 기록으로 미리 예측"

무엇을, 어떤 데이터로 맞힐지가 정해짐.

문제 정의 = 비즈니스 문제를 데이터 문제로 변환하는 단계

해결방안 탐색: 도구와 사람이 있나 없나 (2×2)

타당성 검토 3가지

경제적

남는 장사인가

분석 비용 vs 퇴사 줄여 아끼는 채용·교육비

데이터

데이터가 있나, 쓸 만한가

근태 기록이 1년치뿐, 면담 기록은 종이

기술적

만들 수 있나

지금 인력과 시스템으로 예측 모델 구현 가능?

"데이터 문제로 변환"은 문제 정의 단계예요. 문제 탐색(찾기)과 헷갈리지 마세요. 타당성 "아닌 것"으로 정치적, 법적 타당성 같은 보기가 나와요. 정답은 경제적, 데이터, 기술적 셋.

PART 2 · 상향식과 혼합 (10~11쪽)

4화

상향식: 뭐가 문제인지 모를 때는 데이터부터

10쪽
한 줄 핵심"요즘 매장 분위기가 안 좋다는데 이유를 모르겠다." 이럴 땐 질문부터 세우기 어려우니 데이터를 있는 그대로 보며 "무엇(What)이 보이나"를 찾아요. 정답 없이 끼리끼리 묶는 비지도학습, 일단 만들어 보는 프로토타이핑이 무기.
상향식 4단계프로세스에서 요건으로
프로세스
분류→프로세스
흐름 분석→분석요건
식별→분석요건
정의

매장 업무를 오픈, 피크, 마감으로 나누고(분류) → 각 업무의 흐름과 데이터를 따라가 보고(흐름 분석) → "여기서 분석이 필요하다" 지점을 찾고(식별) → 구체적으로 적음(정의).

정답(이름표) 없이 비슷한 직원끼리 묶어 봤더니 새 문제가 보임 = 비지도학습으로 찾은 과제

비지도학습정답 없이 데이터끼리의 패턴(묶음, 함께 나타나는 것)을 찾는 방법. 15장 군집분석, 연관규칙
프로토타이핑완벽한 정의 없이 일단 시안을 빨리 만들어 보여 주고, 반응을 보며 고쳐 나가는 방식
Why보다 What하향식은 "왜 그런가"를 파고, 상향식은 "무엇이 있나"를 관찰
프로토타이핑은 왜 필요할까

점장들에게 "어떤 분석이 필요하세요?" 하고 물으면 대개 "글쎄요"라는 답이 와요. 사용자도 자기가 뭘 원하는지 모르기 때문이에요.

그래서 대충이라도 "주말 오픈조 위험 알림" 화면을 만들어 보여 주면 "이거 좋네, 근데 마감조도 보고 싶어"처럼 진짜 요구가 나와요. 6장의 프로토타입 모델과 같은 생각이에요.

5화

넓게 펼치고, 좁게 고르기: 혼합 접근

11쪽
한 줄 핵심실제로는 둘을 섞어요. 데이터를 보며 아이디어를 넓게 펼치는 발산 = 상향식, 그중 쓸 만한 걸 골라 검증하는 수렴 = 하향식. 대표 예가 디자인 싱킹.
디자인 싱킹 5단계사람에서 출발
공감하기→문제 정의→아이디어 도출→프로토타입→테스트

김 팀장이 새벽 오픈조에 하루 같이 서 보고(공감) → "혼자 오픈하면 겁나고 버겁다"(정의) → 2인 오픈, 원격 도움 버튼 등(아이디어) → 3개 매장에 시범 운영(프로토타입) → 퇴사율 비교(테스트).

"발상수하": 발산은 상향, 수렴은 하향. 다이아몬드 왼쪽 절반이 위로 올라가는(상향) 모양이라고 떠올려도 좋아요.
디자인 싱킹은 공감하기로 시작해요. 문제 정의가 먼저 나오는 보기는 오답.

끝

확인 8문제

답을 떠올려 본 뒤 눌러서 확인하세요.

하향식 4단계 순서는? 상향식은?

하향식: 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토. 상향식: 프로세스 분류 → 흐름 분석 → 분석요건 식별 → 분석요건 정의.

비즈니스 문제를 데이터 문제로 바꾸는 단계는?

문제 정의. "퇴사가 많다" → "90일 내 퇴사자를 근태 데이터로 예측".

비즈니스 모델 5영역은? 경쟁자는 여기 들어가나?

업무, 제품, 고객, 규제와 감사, 지원 인프라. 경쟁자는 회사 밖을 보는 범위 확장 관점이라 아님.

STEEP의 다섯 글자는?

사회, 기술, 경제, 환경, 정치. 교육, 법률은 없음.

타당성 검토 3가지는?

경제적, 데이터, 기술적 타당성.

상향식에서 쓰는 방법 두 가지는? Why와 What 중 무엇을 보나?

비지도학습, 프로토타이핑. "무엇(What)"이 있는지 데이터 그대로 관찰.

혼합 접근에서 발산과 수렴은 각각?

발산 = 상향식, 수렴 = 하향식 ("발상수하"). 디자인 싱킹은 공감하기로 시작.

과제 관리 5요소와 프로젝트 관리 10영역에 없는 것을 하나씩?

5요소에 분석가 인원 수는 없음(데이터 양, 속도, 데이터 복잡성, 분석 복잡성, 정확도와 정밀도). 10영역에 보안은 없음.

7장 한 문장

김 팀장은 문제가 주어지면 하향식(탐색: 업제고규지·STEEP → 정의: 데이터 문제로 변환 → 해결방안 → 타당성: 경제·데이터·기술), 모르면 상향식(비지도학습, 프로토타이핑)으로 과제를 찾고, 발산(상향)과 수렴(하향)을 섞어 고른 뒤, 정의서로 정리해 5가지 요소와 관리 10영역으로 굴린다.
