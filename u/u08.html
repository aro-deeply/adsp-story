1화

과제가 열 개 쌓였다: 뭘 기준으로 줄 세우나

11쪽
한 줄 핵심돈도 사람도 한정돼 있으니 얼마나 돈이 되나(시급성 = Value)와 얼마나 품이 드나(난이도 = 데이터의 3V)를 따져 줄 세워요. 투자 대비 효과, 즉 ROI의 눈으로 보는 거예요.
IT 프로젝트 기준 (ISP)

전략적 중요도 + 실행 용이성

전략적 중요도: 전략적 필요성(비전, KPI와 맞나), 시급성(늦어지면 생기는 위험)
실행 용이성: 투자 용이성(예산, ROI), 기술 용이성(구현 난이도)

분석 과제 기준 (ROI 관점)

시급성 + 난이도

시급성 = 비즈니스 효과(Return) = Value
난이도 = 투자 비용(Investment) = Volume, Variety, Velocity

ISP정보전략계획. 회사의 중장기 IT·분석 마스터플랜을 세우는 계획 작업
ROI투자 대비 수익. 넣는 것(Investment) 대비 돌아오는 것(Return)
KPI핵심성과지표. 전략적 필요성을 따질 때 "이 과제가 KPI와 이어지나"
"시급성과 관련된 V는?" → Value 하나뿐. 나머지 3V(Volume, Variety, Velocity)는 전부 난이도(돈과 품) 쪽.

사분면에 과제를 올려 보니

11쪽
한 줄 핵심세로축 시급성(현재/미래), 가로축 난이도(어려움/쉬움). 제일 먼저 3사분면(지금 급하고 쉬움), 제일 나중 2사분면(나중이고 어려움). 가운데 순서만 기준에 따라 갈려요.
우선순위를 시급성에 둘 때
Ⅲ→Ⅳ→Ⅱ
우선순위를 난이도에 둘 때
Ⅲ→Ⅰ→Ⅱ

1사분면(급하지만 어려움)은 경영진 판단이나 데이터 범위를 줄여 난이도를 조정하면 순서를 당길 수 있어요.

시작은 둘 다 Ⅲ, 끝은 둘 다 Ⅱ. 가운데만: "시사, 난일" (시급성 → 4, 난이도 → 1).
"시급성이 기준이면 급한 Ⅰ이 둘째 아닌가?" 하고 직관으로 풀면 틀려요. 많은 수험생이 거꾸로 느끼는 부분인데, 시험은 교재 문장 그대로(시급성 Ⅲ→Ⅳ→Ⅱ, 난이도 Ⅲ→Ⅰ→Ⅱ) 채점해요. 이유를 만들지 말고 "시사, 난일"로 통째로.

계획만으론 안 굴러간다: 분석 거버넌스

12쪽

회사 건강검진: 체력(준비도)과 실력(성숙도)

12쪽
한 줄 핵심대표님: "우리 회사, 분석 잘하는 편이야?" 답하려면 두 가지를 따로 재요. 분석할 기초 체력이 있나(준비도, 6개 영역), 실제로 얼마나 잘 쓰고 있나(성숙도, 4단계).

분석 준비도 6개 영역 = 기초 체력 검사표

분석 업무 파악

인력 및 조직

분석 전문가, 전담 조직이 있나

분석 기법

업무별 적합한 기법을 쓰나

분석 데이터

데이터가 충분하고 믿을 만한가, 마스터 데이터 관리(MDM)

분석 문화

"IT문데기인파": IT 인프라, 문화, 데이터, 기법, 인력·조직, 업무 파악. "분석 성과"는 없어요.

확산전사 차원에서 관리·공유, 분석 COE 운영빅데이터 관리 환경

6화

검진 결과표: 우리 회사는 어느 칸?

13쪽
한 줄 핵심가로축 준비도(체력), 세로축 성숙도(실력)로 2×2. 김 팀장 회사는 처음엔 준비형이었다가, 도구와 인력을 들이며 도입형, 결국 확산형을 목표로 가요.

빨간 번호 = 김 팀장 회사의 길: ① 준비형 → (도구·인력 투자) ② 도입형 → (현업 활용) ③ 확산형

도입형

체력은 좋은데 실력은 아직

준비도 높음, 성숙도 낮음. 장비 다 갖춘 헬스 초보. 바로 도입(운동 시작)만 하면 됨.

정착형

체력은 약한데 실력은 있음

준비도 낮음, 성숙도 높음. 맨몸으로 몇 가지 운동을 잘하는 사람. 기반을 다져 정착시켜야 함.

도입형이 제일 헷갈려요. 이름이 "도입"이라 준비도가 낮을 것 같지만 반대예요. "준비가 다 돼서 바로 도입할 수 있는 회사" = 준비도 높음, 성숙도 낮음.
축부터: 가로 = 준비도, 세로 = 성숙도. 대각선 짝: 둘 다 낮음 준비형 ↔ 둘 다 높음 확산형. 나머지 둘은 "도입형 = 준비도만 높음", "정착형 = 성숙도만 높음".
7화

"퇴사율"이 팀마다 다르다: 데이터 거버넌스와 분석 플랫폼

13쪽
한 줄 핵심인사팀은 "퇴사자 ÷ 연초 인원", 매장운영팀은 "퇴사자 ÷ 평균 인원"으로 계산해 숫자가 달라요. 그래서 데이터에 원칙, 조직, 프로세스를 세워 표준을 맞추는 게 데이터 거버넌스. 그 위에서 분석이 돌아가는 바탕이 분석 플랫폼.
원칙 (Principle)

지켜야 할 규칙

"퇴사율은 평균 인원으로 나눈다", 보안·품질 기준

조직 (Organization)

누가 책임지나

데이터 관리자, 데이터 담당 조직

프로세스 (Process)

어떻게 관리하나

정의 변경 요청, 승인, 점검 절차

주요 관리 대상마스터 데이터(직원, 매장처럼 기준이 되는 데이터), 메타 데이터(데이터에 대한 설명), 데이터 사전(용어와 정의 모음)
체계데이터 표준화(용어, 명명 규칙 통일), 데이터 관리 체계(메타 데이터, 사전 관리), 데이터 저장소 관리, 표준화 활동(지켜지는지 점검)

분석 플랫폼: 좁은 뜻 ⊂ 넓은 뜻

분석 애플리케이션은 협의가 아니라 광의에 들어가요. 협의는 "분석 그 자체를 돌리는 심장" 3개(처리 프레임워크, 분석 엔진, 라이브러리)만. 또 데이터 거버넌스 구성요소에 하드웨어는 없어요.
8화

분석가들을 어디에 앉히나: 분석 조직 3유형

13쪽
한 줄 핵심분석 전담 조직(DSCoE)을 한곳에 모으거나(집중형), 따로 두지 않고 부서마다 알아서 하거나(기능형), 전문가를 부서에 보내거나(분산형). 인사 담당자에겐 익숙한 조직 설계 문제예요.
집중형

한곳에 모으기

독립 전담 조직이 전사 우선순위를 정해 수행. 단점: 현업 부서에도 분석하는 사람이 있으면 중복 업무(이원화) 가능성.

기능형

부서마다 알아서

별도 분석 조직 없음. 각 부서가 자기 업무를 직접 분석. 단점: 부서 안만 봐서 전사 관점 분석이 어려움.

분산형

전문가 파견

전담 조직의 인력을 현업 부서에 배치. 장점: 현장 가까이 있어 신속한 실무 적용.

"집기분" 그리고 한 단어씩: 집중형 = 중복, 기능형 = 조직 없음, 분산형 = 파견.
"분산형"이라는 이름 때문에 "조직 없이 흩어져 있다"로 오해하기 쉬워요. 그건 기능형이에요. 분산형은 전담 조직이 있고 그 인력을 부서에 나눠 보낸 것.
끝

확인 8문제

답을 떠올려 본 뒤 눌러서 확인하세요.

시급성과 연결된 V는? 난이도는?

시급성 = 비즈니스 효과 = Value. 난이도 = 투자 비용 = Volume, Variety, Velocity.

가장 먼저 할 사분면과 가장 나중 사분면은?

먼저 Ⅲ(현재·쉬움), 나중 Ⅱ(미래·어려움).

시급성 기준 순서와 난이도 기준 순서는?

시급성 Ⅲ → Ⅳ → Ⅱ, 난이도 Ⅲ → Ⅰ → Ⅱ. "시사, 난일".

데이터 분석 로드맵 3단계는?

체계 도입 → 유효성 검증(파일럿) → 확산 및 고도화.

분석 거버넌스 5요소와 데이터 거버넌스 3요소는?

분석: 조직, 프로세스, 시스템, 데이터, 분석 교육 및 마인드 육성. 데이터: 원칙, 조직, 프로세스. 예산, 하드웨어는 없음.

준비도 6영역에 "분석 성과"가 있나? 성숙도 순서와 기반 모델은?

없음. 6영역은 업무 파악, 인력·조직, 기법, 데이터, 문화, IT 인프라. 성숙도는 도입 → 활용 → 확산 → 최적화, CMMI 기반.

준비도 높고 성숙도 낮으면? 준비도 낮고 성숙도 높으면?

앞은 도입형(바로 도입 가능), 뒤는 정착형(제한적으로 쓰는 중, 정착 필요).

업무 중복 가능성이 있는 조직 구조는? 별도 조직이 없는 구조는?

중복 = 집중형, 조직 없음 = 기능형. 파견은 분산형. 협의의 분석 플랫폼에 분석 애플리케이션은 없음(광의).

8장 한 문장

과제가 쌓이자 김 팀장은 시급성(Value) × 난이도(3V) 사분면으로 줄 세우고(Ⅲ 먼저, Ⅱ 나중, 시사·난일), 도입 → 검증 → 확산 로드맵을 그린 뒤, 회사의 준비도(6영역)와 성숙도(도활확최, CMMI)를 재서 준비·정착·도입·확산형 중 어디인지 진단하고, 분석 거버넌스 5요소, 데이터 거버넌스(원칙·조직·프로세스), 분석 조직(집중·기능·분산형)으로 회사 전체의 분석 체계를 세운다.
